The problem

Global skills fire on their own

You install a skill globally to reuse it across projects. Then the agent starts invoking it by itself — sometimes you want that, often you don't.

Frontmatter means preloading

Claude Code, Codex, opencode, Cursor, Pi — every harness implements skills differently, but they share one behavior: once a skill's frontmatter is loaded, the agent is bound to it.

So you end up managing skills

Pruning, moving, renaming — babysitting your skill folder so the agent doesn't grab the wrong thing.

The fix

No preloading

Skillbox keeps skills outside the harness. Nothing sits in the agent's context, so nothing fires by accident.

On demand, by name

Say "use this skill" and the agent searches Skillbox, surfaces the skill, and loads it — right then, and only then.

Total control

You decide when a skill enters the conversation. One CLI, every agent, zero babysitting.

The whole ecosystem, one flag away

Search skills.sh without leaving the CLI

skillbox search react --web queries the public skills.sh directory. Your registry stays the default; the web is always explicit.

Use once or keep it

Fetch any skill by owner/repo/skill for one-off use, or skillbox add it so it resolves by name from then on — always clearly marked unverified.

Try it

$ skillbox list "design for chatbot"
$ skillbox search effect
$ skillbox fetch frontend --print
$ skillbox info frontend
# pull a skill into a temp dir for the agent to use
$ skillbox fetch frontend --to-temp
# reach the skills.sh directory on demand
$ skillbox search react --web
$ skillbox add vercel-labs/agent-skills/vercel-react-best-practices

Install

# Homebrew
$ brew install hhushhas/tap/skillbox

# Cargo
$ cargo install --git https://github.com/hhushhas/skillbox
